Tutorial 1
+++++++++++++

Purpose
********
The purpose of this first tutorial is to understand the most basic functionalities of
the Geospatial Microplanning Toolkit (GMT). No previous knowledge of this application
is required.

To achieve this, the following is introduced:

#. Access GMT
#. Login / Access to data
#. Familiarize yourself with the dashboard
#. Obtain the data to do the microplanning
#. Review the health facility list, do minor modifications
#. Review the settlement list, do minor modifications
#. Perform the microplanning
#. Review the microplan
#. Sync changes back to the database
#. Print the microplan

Note: "clicking" in this guide can be substituted by "tapping" as well - for instance
if you are working on a tablet.

----------------------------

Let's Get Started!
******************

Access GMT
=========

For the training, in a browser, ideally Google Chrome, navigate to

https://uat.gmt-pilot.health/

Note that this is the URL to do **only the training**.

Once you are in the field doing the real microplans, the URL you should use is:

https://gmt-pilot.health/

You should see the following:

.. image:: /content/_images/landing_page.png
    :align: center

Login / Access to data
======================
If you would just like to consult the data and you have no intention to edit,
you can simply choose "Direct access to the Map" and you will be directed to choose which
module you would like to consult.

If you would like to do any editing, you should provide your credentials here. You will
be redirected to choose which microplanning module you would like to consult.

.. note::
  If you are working on a tablet, you should be adding the application to the
  tablet instead.

Follow the steps shown below to do so:

.. image:: /content/_images/install_GMT.jpg
          :align: center

Google Chrome. Click on it and select "Install App".

.. image:: /content/_images/install_app_2.jpg

In either case, you should now see the app icon in your applications:

.. image:: /content/_images/tablet_home.jpg

|
You should also install the documentation app to have it available offline. With the Chrome Browser,
navigate to the help:

https://api-uat.gmt-pilot.health/help/index.html

Similarly to the above, you are either prompted directly to install the app, or else you
can install it via the 3-dot menu from Chrome:

Dashboard and taking data offline
=================================

You will note that you are logged in when your email address shows on the top right.

On the dashboard, you will be able to navigate to the wards of your interest. You can
use the map to navigate by clicking on the areas of interest to you, alternatively use the list on the left or else the search.

We will be assuming the role of a ward focal person in "Amuzi", a Ward located in LGA "Ahiazu-Mbaise" in the State "Imo".

Let's use the search: type "ahiaz" in the search bar.

You should see:

.. image:: /content/_images/search_ahiaz.png
    :align: center

|
Click on the name "Amuzi" - note how the list and map change. On the list,
note that there is one health facility listed for this Ward. Click on a "+" next
to another Ward to see the health facilities for that respective Ward.

.. image:: /content/_images/PD_HF_wards.png
    :align: center
|
We will be conducting microplanning in the field where there may not be any connectivity.
Thus, the application is designed to work also offline. Accordingly, we will need to take the data
for this Ward offline to be able to see or edit the microplan.
For that, click on the "Take Offline" button. Once the data has been downloaded, you will
be able to see a green tickmark indicating that this data is available.


By clicking on the "Show offline" tickbox, you can see what data is available for editing. In your case, you should only see Ward Amuzi now.

.. image:: /content/_images/show_offline.png
    :align: center
|
Click now on the the name "Amuzi" to enter the microplanning screen.

Review the Health Facility list
===============================

You will be guided through the interface step by step. Let's start with the health facility list.
The current interface has a list on the right and a map on the left.

.. note::
  The global "Edit" button at the top is toggled on per default when you are
  logged in. If you don't plan to do any edits, you can toggle this button off
  to avoid changing any data inadvertently.

  .. image:: /content/_images/microplan_landing_page.png
      :align: center

In the first step you should review the health facility list.

.. hint::
  Our goal is to identify all health facilities in the current ward that we need
  to consider for microplanning. We also need to make sure they are at the right
  place and they have the right name.

In this Ward, there is one health facility as shown in the health facility list.

.. note::
  Note the following:

  #. The color next to the health facility indicates the color the health facility label has on your microplan map.
  #. AKA stands for "Also Known As", in this case potential other names for that same health facility. We will see this later.
  #. Catchment population is currently 0 - we have not defined catchments yet. We will see this later.
  #. Health facilities can have error icons listed under the "Error type" column.

Since this health facility has not been assigned any settlement at this point, it shows an error at the moment":

.. image:: /content/_images/HF_list.png
    :align: center
|
We can access all information about this health facility by either clicking on the
health facility on the map or clicking on the name of the health facility on the list.
Do either of those two to access the health facility tab.

Note that the health facilities are depicted with the following icon on the map:

Review the Settlement list
============================

What are we referring to when we say "settlement"? It is a place that health workers refer to
where they are planning routine immunization activities.

.. hint::
  Next, our goal is to identify all settlements in the current ward that we need
  to consider for microplanning. We need to make sure they are at the right place and that they have the
  right name.

To do this, we will look at the settlement list. Click on the "Settlements" button.

.. image:: /content/_images/settlements_button.png
    :align: center
|
.. note::
  There are similarities to the health facility list:

  #. AKA stands for "Also Known As", in this case potential other names for that settlement. We will see this later.
  #. Settlements can have error icons listed under the "Error type" column.
  #. Each settlement has a calculated population value, coming from a population model. We can add a field estimate to a settlement, as we will see shortly.

Since this settlement has not been assigned to a health facility, it shows the
error icon "Unclaimed":

.. image:: /content/_images/settlement_list.png
    :align: center
|
We can access all information about this settlement by either clicking on the
settlement on the map or clicking on the name of the settlement on the list.
Do either of those two to access the settlement tab. Note that the settlements
are depicted with the following icon on the map:

.. image:: /content/_images/settlement_map.png
    :width: 100
    :align: center

Settlement details
-------------------

You landed on the "Catchment" tab. We will look at this later. Instead, click on "Details".

On the top, you will see the name of the settlement. Similar to what we saw for the
health facility, we can click in the name field directly to change the name. Let's
assume that there was a typo for this settlement and correct it to "Umowasi".

For our example, we will consider that we know the actual population of this
settlement. We have the possibility to add this information here. Enter the
field estimated population in the corresponding field - enter 3500.

If you wonder where the computed population comes from, this is explained in :ref:`content/background/10background:population`.

Let's also assume that this settlement is a Polio high-risk settlement - we can
add this information here as well.

.. image:: /content/_images/settlement_detail.png
    :align: center
|
Close the settlement tab and note that the settlement name has been corrected
and the field estimated population has replaced the computed population that was
shown before.

  We reached our second goal: at this step, we imagine the settlement list for this Ward is complete -

Perform Microplanning
=====================

.. hint:
  Our next goal will be to define the catchment area for the health facilities of
  this Ward. We start simple: one health facility, one settlement.

Navigate back to the health facility tab. Click the health facility on the list to
enter the "Catchment" information for the health facility.

Note that currently there are no included settlements in the catchment of this
health facility.

.. image:: /content/_images/HF_not_claiming.png
    :align: center
|
Below, you see the suggested settlements for this health facility. We
would like to add the settlement that is closest to the health facility. Thus, click
on "Distance" and sort the table by distance.

We can see that our settlement is the closest to this health facility. We can double
check that it's the correct settlement by clicking on the magnifying glass. Having
verified that, let's add it to the health facility catchment using the "+" icon.

.. image:: /content/_images/add_to_catchment.png
    :align: center
|
.. note::
  This resulted in a few things:

  #. The settlement has been added to the list of "Included Settlements".
  #. You could remove it from this list again by clicking on the "x".
  #. The map on the right shows the delineation of the catchment for this health facility.
  #. The color of the catchment on the map corresponds to the color of the health facility.
  #. The pattern of the catchment is explained in the legend.

.. image:: /content/_images/catchment_added.png
      :align: center
|
Let's take a closer look at the "Included Settlements" now.

Included Settlements
--------------------

Let's first review the intervention strategy for our settlement. We have the options
"Unknown", "Fixed-Post", "Outreach" and "Mobile". Try to assign different strategies
for your settlement. Note that with each change, the pattern for the catchment on
the map changes to reflect that. The default strategy that is chosen when adding a
settlement always corresponds its distance from the health facility. Meaning that if
a settlement is within 2km, the default strategy is "Fixed-Post", if it's between 2-5km
the default strategy is "Outreach" and if it's above 5km it is "Mobile".

For "Fixed-Post" strategy:

.. image:: /content/_images/fixed_post.png
    :align: center
|
For "Outreach" strategy:

.. image:: /content/_images/outreach.png
    :align: center
|
For "Mobile" strategy:

.. image:: /content/_images/mobile.png
    :align: center
|
Since this settlement is within 2km of our health facility, let's assign it
the "Fixed-Post" strategy.

.. image:: /content/_images/strategy.png
      :align: center
|
The catchment total population of this health facility is summarized and corresponds
to the target population of the settlements assigned to this health facility.
For now this was fixed at 5% of the total population for the settlement in our catchment.
In the future, this will be a parameter that can be defined. Let's not worry about the
other columns for now - we will look at this later.

.. image:: /content/_images/population_summary.png

Review Microplanning
=====================

.. hint::
    Our next goal will be to review the microplan.

Navigate back to the health facility list by either clicking on "Health Facilities"
or else clicking on the "x".

Note that the error icon has disappeared, since we have added a settlement to
the catchment of this health facility. Additionally, the catchment population for
this health facility now shows 3500 - the population we have entered for the
settlement. If you click on the arrow next to the health facility, you can see
what settlement is part of the catchment.

.. image:: /content/_images/hf_list_catchment.png
      :align: center
|
If you navigate to the settlements list, you will also see that the error icon
for the settlement has disappeared, since the settlement has been added to a
health facility.

.. hint::
    We reached our fourth goal: We reviewed the health facility and settlement list,
    we reviewed the catchments and our microplan is complete.

Synchronize the changes back to the server
==========================================

.. hint::
    Our next goal is to synchronize our changes back to the server. This section is only
    relevant if you are on https://gmt-pilot.health. It will not work for https://uat.gmt-pilot.health.
    Read the section nevertheless.

.. warning::
  All of the current work has been saved in our browser locally. If we were to lose our
  device, those changes would be lost at the current stage. In order to update the
  GMT database with our changes, we will have to establish connectivity and synchronize
  our changes back with the server.

First, establish connectivity. To synchronize the changes, there are two ways.

We could already click on the "Sync" button, which will directly synchronize all changes
on the device. Let's hold off and first navigate back to the dashboard using the menu at the top.
Click on "Ahiazu-Mbaise".

.. image:: /content/_images/breadcrumbs.png
      :align: center
|

Using the "Show offline" filter, you will see that our Ward has been modified. Let's click
that "Sync" button now.

.. hint::
  We reached our fifth goal: synchronization has been achieved. Only one step left to finalize this tutorial.

----------------------------

Print the PDF of the microplan
==============================

.. hint::
  Our final goal for this first tutorial is the printing of the PDF.

To obtain a printable PDF of the microplan for this ward, we can simply select the
checkbox next to our ward and click on the corresponding "Print" icon at the top.

.. image:: /content/_images/print_pdf.png
      :align: center
|
You will have several options. If you print several Wards at the same time, you can choose to just have
one PDF file per Ward (otherwise, it will generate one PDF containing the data for all Wards).
You can also choose to print a detail page per Health Facility. For our purpose, since we just have
one Ward anyway that we are working on, let's just select the last option "Include one detailed page per
Health Facility". You can ignore the other options for now.

.. image:: /content/_images/print_options.png
      :align: center
|
The PDF will be generated automatically.

.. important::
  You reached the end of Tutorial 1!
